# Security audit

> ## IMPORTANT — change of security model (latest build)
> At the owner's request the passphrase gate and encryption were **removed**. The app now stores a **plain SQLite file in this browser's IndexedDB**. Consequences for the findings below:
> * **S-01 (encryption at rest), S-02 (KDF), S-03 (passphrase policy), S-04 (unlock throttling), S-12 (memory exposure/locking), S-13 (secure wipe as crypto-erase), S-17 (password manager)** describe the *previous* encrypted build and **no longer apply to the shipped app**. The code and tests remain, unused by the UI.
> * **New finding S-20 — High (accepted by owner):** against the brief's *stolen device* and *shared machine* threats there is no protection beyond the operating-system account and browser profile. Anyone with access to the browser profile (or a copy of its storage, or a backup file) can read every transaction. Mitigations the user controls: device lock screen, full-disk encryption, a dedicated browser profile, keeping backups private. Re-enabling encryption is a UI change only (`VaultManager.create/unlock` still exist).
> * Still valid: S-06 (network), S-07 (import sandbox), S-08 (XSS/injection), S-09 (dependencies), S-11 (audit-log integrity), S-15, S-16 (backups are now plain files), S-18 (lost writes).
> * Real-browser evidence added: headless Chromium against the production build recorded **0 non-local network requests and 0 console errors** across setup, a PDF import, every screen, dark and mobile views.


Scope: the Tally PWA in this repository, as built by `npm run build`. Threat model from the brief: stolen device, shared machine, malicious import file, runtime escape.
**Method and limits.** Findings come from code review, automated tests, static analysis of the production bundle, and `npm audit`. **Not done:** a live browser session with DevTools/`netstat`/`lsof` evidence (no browser in the build environment), a penetration test, or a review of the browser/OS itself. Items that need that evidence are marked **needs your verification**.

## Summary
No critical findings. One high-severity integrity bug (S-18, lost writes after a failed save) was found in testing and **fixed**. Remaining items are mitigated, accepted with reasons, not applicable, or marked **needs your verification** because they require a real browser.

## Hardening recommendations before real use
1. Open the built app in a browser, DevTools → Network with "Disable cache" off, and confirm no requests after the initial load (S-06).
2. Serve with the CSP as an HTTP header (`Content-Security-Policy`), plus `Cross-Origin-Opener-Policy: same-origin` and `Referrer-Policy: no-referrer`.
3. Try the importer on **your own real statements** and keep the generated "statement check" green.
4. If you want SQLCipher-grade page-level encryption or OS-level key storage, build the Tauri variant; this PWA encrypts the whole database file per save.
